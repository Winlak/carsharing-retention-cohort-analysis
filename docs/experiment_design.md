# Схема эксперимента: вернуть пользователя без второй поездки к D3

## Гипотеза

Если на D3 после первой завершённой поездки показать пользователю без повторной completed ride релевантный CRM-триггер (маршрутный сценарий + ограниченный кредит), то classical D30 вырастет относительно текущего опыта. Гипотеза не следует из cohort chart автоматически: график задаёт размер сегмента и prior, а эффект проверяет рандомизация.

## Популяция и assignment

- **Eligibility:** первая завершённая поездка 3 дня назад; нет completed ride на cohort age 1–3; нет активного другого CRM-experiment; согласие на CRM по политике продукта.
- **Единица:** `user_id`; sticky assignment до показа сообщения.
- **Strata:** город × acquisition channel. Внутри каждой страты — 1:1 control/treatment; блоковая рандомизация устраняет случайный перекос важных наблюдаемых факторов.
- **Control:** текущий опыт без нового триггера. **Treatment:** один заранее зафиксированный recovery/CRM-пакет. Не смешивать скидку, push и redesign в один treatment, иначе lift нельзя приписать механике.
- **Primary analysis:** intention-to-treat по всем назначенным eligible users; не отбрасывать непрочитавших или неактивировавшихся после assignment.

## Метрики и анализ

| Роль | Метрика | Определение |
|---|---|---|
| Primary | Classical D30 | ≥1 completed ride ровно на `cohort_date + 30`; знаменатель — все назначенные с наблюдаемым D30. |
| Secondary | Rolling D30 | Последняя observed completed ride на D30 или позже. |
| Diagnostic | Completed rides D4–D7 | Ранняя активация *после* assignment; не заменяет primary. |
| Guardrail | Отмены/ошибки, support contacts | На назначенного пользователя; следим, чтобы лечение не повышало фрикцию. |
| Guardrail | Cost per incremental retained user и валовая маржа | Для оценки окупаемости, не только роста rate. |

Заранее фиксируются alpha 0.05, двусторонний тест разницы пропорций, 95% CI эффекта в percentage points, minimum detectable effect и горизонт 30 дней. Если тестируют несколько treatments или primary/secondary решения, применяется заранее указанная коррекция или hierarchical gate. Не останавливать тест по «красивому» промежуточному p-value.

## Размер выборки

Для planning использовать baseline classical D30 из последней сопоставимой eligibility population и минимально полезный бизнес-эффект, а не observed gap между early-activity сегментами. Размер на группу для равных долей можно считать через power для двух пропорций; после стратификации увеличивать на ожидаемый остаточный дисбаланс/потери данных. Итоговый расчёт должен быть сделан на реальном baseline до запуска.

## Первая ошибка: отдельный эксперимент

Для payment/app/unlock error treatment — понятный recovery flow (повтор платежа, сохранённые параметры, альтернативная доступная машина). Primary — first-completed-ride conversion в 24 часа среди всех назначенных после ошибки; дальний D30 — secondary и также ITT. Это избегает ошибки анализировать «первую ошибку» только среди тех, кто всё же потом активировался.
